# NCNC WebUI 开发说明

NCNC WebUI 是 NCNC 的前端管理界面，负责媒体库、播出日历、订阅、电影添加、下载/上传队列和系统设置等功能。项目使用 Vue 3 + TypeScript + Vite，UI 组件主要来自 Naive UI，后端 API 由独立服务提供。

**环境约定：本项目最终运行和部署环境仅为 Linux，前端静态资源由 Linux 上的后端服务或 Nginx 托管。开发、依赖安装、构建、测试及问题排查均以 Linux 环境为准，不考虑 Windows 生态的兼容、适配或专用依赖问题。即使源码目录位于 Windows 主机，也不改变这一约定；最终构建和运行验证应在 Linux 主机或 Linux 容器中完成。**

> **代码检测必须在 Linux 环境进行。** `npm run type-check`、`npm run lint`、`npm run test:unit`、`npm run test:e2e`、`npm run build-only` 和 `npm run build` 等检查结果，只有在 Linux 主机或 Linux 容器中执行才作为有效结果。不要在 Windows 与 Linux 之间共用 `node_modules`；不同平台的 Rollup、esbuild 等原生可选依赖会互相覆盖。切换平台时应删除 `node_modules`，并在目标 Linux 环境重新安装依赖。

## 快速开始

环境要求：Linux + Node.js 20（Docker 使用 Linux 容器和 Node 20）。以下命令均在 Linux 环境执行。

```bash
npm install
npm run dev
```

开发服务器默认使用 `http://localhost:5173`。开发模式下，统一 Axios 实例会把 API 请求发送到 `http://localhost:8000`；生产构建使用相对路径，由 Nginx 将 `/v1/*` 等请求转发给后端。

常用命令：

```bash
npm run type-check       # Vue/TypeScript 类型检查
npm run build-only       # 仅构建 dist
npm run build            # 类型检查并构建
npm run lint             # ESLint（带自动修复）
npm run format           # Prettier 格式化 src
npm run test:unit        # Vitest 单元测试
npm run test:e2e         # Playwright 端到端测试
npm run preview          # 预览已构建的 dist
```

首次运行端到端测试需要安装浏览器：`npx playwright install`。

```text

├─ src/
│  ├─ main.ts                      应用入口：注册 Pinia、路由并挂载 Vue

│  ├─ views/                       路由页面（页面级业务逻辑和页面样式）
│  ├─ components/                  可复用组件
│  │  └─ settings/                 设置页子组件
│  ├─ services/                    后端 API 封装
│  ├─ stores/                      Pinia 状态（用户、主题、消息）
│  ├─ client/                      OpenAPI 生成的 TypeScript Axios 客户端
│  ├─ themes/                      Pink/Blue 主题覆盖配置
```

## 页面与代码位置

所有登录后的页面都挂在 `src/views/MainView.vue` 下。`MainView` 提供顶部标题栏、左侧菜单、内容区 `RouterView` 和右下角浮动操作条。

| 页面 | URL | 入口文件 | 主要职责 |
| --- | --- | --- | --- |
| 登录 | `/login` | [`src/views/LoginPage.vue`](src/views/LoginPage.vue) | 登录布局；表单逻辑在 `src/components/LoginBox.vue` |
| 媒体库 | `/library/media` | [`src/views/MediaView.vue`](src/views/MediaView.vue) | 媒体卡片、搜索、进度、单个媒体刷新 |
| 媒体详情 | `/library/media/:tmdb_id` | [`src/views/MediaDetailView.vue`](src/views/MediaDetailView.vue) | 媒体信息、季/集管理、资源搜索、下载和上传 |
| 播出日历 | `/library/calendar` | [`src/views/AirCalendarView.vue`](src/views/AirCalendarView.vue) | 按日期查看即将播出和已播出内容 |
| 媒体库添加 | `/library/subscribe` | [`src/views/SubscribeView.vue`](src/views/SubscribeView.vue) | 搜索并订阅电视剧/媒体 |
| 电影添加 | `/library/movie/search` | [`src/views/MovieAddView.vue`](src/views/MovieAddView.vue) | 搜索电影、选择路径并添加下载/上传任务 |
| 系统设置 | `/library/settings` | [`src/views/SettingsView.vue`](src/views/SettingsView.vue) | 设置页入口；具体表单在 `settings/WebSettingsContainer.vue` |
| 下载任务 | `/library/downloads` | [`src/views/DownloadTasksView.vue`](src/views/DownloadTasksView.vue) | 查看下载中、暂停、完成及异常任务；每 2 秒自动刷新 |
| 查看日志 | `/library/logs` | [`src/views/LogView.vue`](src/views/LogView.vue) | 按服务器日志日期选择并查看当天日志 |

路由和页面标题统一维护在 [`src/router/index.ts`](src/router/index.ts)。未登录访问受导航守卫保护，会跳转到登录页；根路径会跳转到媒体库。

## 核心组件

播出日历中，已播出分集按 `episode.exists` 区分媒体库状态：绿色表示已入库，琥珀色表示未入库。卡片使用浅色背景、侧边色条和文字标签，顶部提供图例，并跟随明暗主题适配。待播出仍使用主题色，具体播出时间未知的分集保留中性样式。

系统设置 → 媒体库设置提供“是否自动压缩”开关，对应后端 `media_auto_compress`，默认开启。点击保存后对后续处理任务生效；关闭时跳过媒体探测、压缩和字幕提取，MP4/MKV 直接移动，其他需要转封装的格式保留源文件并报错。

媒体页海报右上角在最新正式季度（最大正季号，不含特别篇）的剧集数据完整且全部已播出时显示“季度完结”。优先使用可信 UTC 播出时间，仅有日期时沿用页面的本地日期判断；空季度、缺集或未知日期不标记。标记使用当前主题色填充及圆角边框、白色加粗文字，并随页面时钟更新。

当前 `/v1/settings` 使用 `src/services/settingService.ts` 中的手写类型和请求封装；`openapi.json` 仍为旧版 API，未包含该接口。

- [`MainView.vue`](src/views/MainView.vue)：登录后的应用壳，组合标题栏、菜单、系统信息面板及下载/上传浮动条。
- [`MainMenu.vue`](src/components/MainMenu.vue)：桌面端侧栏和移动端横向菜单；新增页面时通常需要同步菜单项和路由名称。
- `SystemDashboard.vue`：侧栏系统信息展示。
- `DownloadContainer.vue` / `UploadContainer.vue`：浮动条弹出的任务列表；对应的单项组件是 `DownloadItem.vue` / `UploadItem.vue`。
- `MessageContainer.vue`：配合 Pinia 消息状态显示全局提示。
- `settings/SettingsContainer.vue` 和 `settings/WebSettingsContainer.vue`：设置任务列表及 Web 设置表单。

## API 与状态管理

页面直接调用 Axios 的旧代码仍存在，但新功能应优先使用 `src/services` 中的封装，并统一通过 [`src/api/modifiedAxios.ts`](src/api/modifiedAxios.ts) 发请求。该实例会携带 Cookie；收到 401 时清除用户状态并跳回 `/webui/login`。

主要 API 封装：

| 文件 | 负责内容 |
| --- | --- |
| `userService.ts` | 用户登录 |
| `appService.ts` | 重启后端 |
| `downloadService.ts` | 下载列表、清空下载队列 |
| `logService.ts` | 日志日期列表、指定日期日志内容 |
| `uploadService.ts` | 上传列表 |
| `engineService.ts` | 更新全部媒体信息 |
| `scheduleService.ts` | 定时任务查询、更新、重启 |
| `settingService.ts` | 设置查询和保存 |

Pinia 状态位于 `src/stores`：`user.ts` 保存登录用户，`theme.ts` 保存深色模式和主题色，`message.ts` 保存全局提示。`src/client` 是根据 `openapi.json` 生成的代码，不建议手工修改。

后端接口发生变化时，先更新 `openapi.json`，再执行：

```bash
npm run generate-client
```

## 样式与资源

全局样式在 `src/assets/base.css`、`src/assets/main.css`，主题覆盖在 `src/themes`。页面专属样式通常写在对应 `.vue` 文件的 `<style scoped>` 中。Vite 的公共路径是 `/webui/`，图片等静态资源应放在 `public/` 或通过 `src/assets` 引入，避免写死开发机路径。

## 测试与交付检查

以下代码检测必须在 Linux 主机或 Linux 容器中执行。提交前至少运行：

```bash
npm run type-check
npm run test:unit -- --run
npm run build-only
```

涉及路由或用户交互时，再运行对应的 Playwright 测试。首次运行前需执行 `npx playwright install` 安装浏览器。

## Docker 部署

`Dockerfile` 分两个阶段：第一阶段安装依赖并构建，第二阶段将 `dist` 复制到 Nginx。生产环境还需要配套的 Nginx 配置，将前端历史路由和后端 API 正确转发。修改 API 地址、基础路径或代理规则时，应同时检查 `vite.config.ts`、`src/api/modifiedAxios.ts` 和 Nginx 配置。

## 新功能开发建议

新增页面时，按“路由 → 页面组件 → 菜单入口 → API service → 状态”的顺序检查依赖关系。页面之间共享的数据放入 service 或 Pinia；只在单个页面使用的交互状态留在对应 view。处理媒体播出时间时优先复用 `src/utils/airtime.ts`，以保持时区和未知时间的处理一致。
